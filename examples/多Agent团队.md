# 示例：多 Agent 团队的派活与收尾

场景：协调者 agent 带三个成员（写作、剪辑、发布），用户交付一个「做一期视频并多平台发布」的活。

## 派活

1. `list_bots` 现查团队：写作 agent、剪辑 agent、发布 agent 都在，各自空闲。
2. 拆活点对点派：
   - 写作 agent：写脚本，验收＝1500字段点稿，路径约定。
   - 剪辑 agent：等脚本成稿后剪 3 分钟成片，验收＝1080p/竖屏。
   - 发布 agent：拿成片发三个平台，验收＝三平台巡检通过。
3. 消息自包含：每条都带背景、目标、验收标准、依赖（剪辑依赖写作成稿）。
4. 告诉用户「问了这三个、各做什么、会回报」，然后等回执，不轮询。

## 制度下发

把「交付后按五段建档」下发全队，要求回执写明「档案写在哪、什么时候写的」。写作 agent 回了路径和行数算回执；剪辑 agent 只回「知道了」不算，催它补具体回执。

## 收尾（用户说「收尾」）

协调者做自己的五步，外加两条：

1. 索引复核：项目 `_索引.md` 与团队 `任务档案/_索引.md` 逐条对账，发现一行指向不存在的成片文件，当场删掉该行。
2. 档案抽查：
   - 写作 agent：`任务档案/写作/YYYY-MM-DD-脚本.md` 存在 ✓
   - 剪辑 agent：`任务档案/剪辑/YYYY-MM-DD-成片.md` 缺失 → 当场让剪辑 agent 补写并回执
   - 发布 agent：档案在，但第5段「事实核对」空着，而它宣称「三平台已发布」——按事实条款要求补依据（巡检截图/命令输出），补不了就标「待核实」。

## 报告

向用户汇报：
- 保留：终稿脚本、成片、三份档案、两处索引
- 删除：草稿 v1/v2、临时导出脚本、旧的备份副本
- 偏移：无范围蔓延；发布 agent 的「已发布」已补证据
- 事实依据：`list_bots 实测 22:33`、`task_read 返回三份档案路径`、`三平台巡检日志`
