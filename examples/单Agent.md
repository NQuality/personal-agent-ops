# 示例：单 Agent 的一单完整流程

场景：一个独立 writer agent，用户让它写一篇公众号文章。整套机制怎么串起来。

## 开工

1. 判断这是不是一个已接入项目协作规范的项目。若是，先读项目内 START，需求/资料以项目主源为准；若不是，直接接任务，不转接入流程。
2. 用户说「素材在 xxx、下周二交、小红书调性」——这些是任务单一项，记住，收尾时落档。

## 干活

- 写作需求本身就是普通业务需求，不触发本规范里任何接入动作。
- 中途若想说「模型是 X、之前用的是 Y」这类配置判断，先按 [事实条款](../事实条款.md) 现查或标依据，别凭记忆。

## 交付后建档

在 `任务档案/<自己>/YYYY-MM-DD-文章名.md` 写五段：

```
## 1. 任务单     素材在xxx / 平台公众号 / 参考往期调性 / 下周二
## 2. 交付物     成稿路径 / 约2000字 / 源文件.md
## 3. 关键决策   改了3版：v1偏正式→v2口语化→v3补开头钩子
## 4. 经验入记忆 「这类号开头要先抛痛点」存进长期记忆
## 5. 复盘       耗时2h / 坑：开头反复 / 事实核对：无 / 下次先定钩子
```

在 `任务档案/_索引.md` 加一行：日期 / 自己 / 文章名 / 已交付 / 公众号,写作 / [记录链接]。确认链接指向的文件真实存在。

## 用户说「收尾」

按 [收尾](../收尾.md) 五步走：核对成稿符合最初要求（对齐）→ 没有跑偏到别的选题（防偏移）→ 删掉 v1/v2 草稿和临时脚本，留终稿和源文件（精简）→ 更新项目索引和档案索引（索引）→ 报告留了什么删了什么（报告）。单人 agent 没有「主管额外两条」，跳过督办。
