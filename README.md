# Personal Agent 运营规范（personal-agent-ops）

给「长期陪伴单个用户、带记忆与文件系统的 AI agent」用的一套运营机制。它让 agent 跨会话、跨项目地保持可靠：每单留痕、收尾干净、说话有据、带团队能督办、记忆常新、系统自治。

## 它解决什么

一个 agent 用久了会有六类隐患，这套机制逐一堵上：

| 隐患 | 对应机制 |
|---|---|
| 干完就忘，下次重复踩坑、无法复盘 | 交付档案 |
| 项目越做越散，偏移、临时文件堆积、交付状态说不清 | 收尾 |
| 凭记忆说配置/数字/状态，说错还不自知 | 事实条款 |
| 带多个 agent 时派活无痕、制度下发石沉大海 | 多 Agent 督办 |
| 主记忆被流水挤满、必读事实被滚动挤走 | 记忆维护 |
| 维护制度一堆没人盯、异常要么漏报要么事事打扰用户 | 系统自治维护 |

另有一篇 [协作接入](协作接入.md) 说明它和「项目协作规范」（如 `agent-collaboration`）怎么分工——那是给单个项目用的，本规范不替代它。

## 和项目协作规范的关系（重要）

这是两层，别混：

- **项目协作规范管项目**：某个项目内部的需求、状态、台账、知识，只放项目主源。代表技能：`agent-collaboration`。
- **本规范管 agent 自己**：交付档案放哪、收尾怎么做、事实现查、团队怎么督办——与具体项目无关。

两者通过 [协作接入](协作接入.md) 衔接：业务项目开工先按项目规范接入，本规范的档案只记「这一单怎么交付的」，引用项目文档而不复制。

## 组成部分

```
personal-agent-ops/
├── SKILL.md         入口：何时触发、读哪篇、边界
├── README.md        本文件：全景与安装
├── 交付档案.md       五段模板、索引、记忆/档案分工、改名清单
├── 收尾.md           对齐/防偏移/精简/索引/报告 + 主管额外两条
├── 事实条款.md       易腐事实现查、依据、证伪纠正、交付自查
├── 协作接入.md       与项目协作规范的分工及最小接入
├── 多agent督办.md     派活预检三关、派活路由、制度回执、收尾抽查
├── 记忆维护.md        主记忆体检、无损精简、源头规矩、留痕
├── 系统自治维护.md    定期巡检、分级自愈、看门兜底、静默与留痕
└── examples/
    ├── 单Agent.md    单人 agent 的一单完整流程
    └── 多Agent团队.md 带团队的派活与收尾
```

## 安装与分发

作为技能包分发时，把整个 `personal-agent-ops/` 目录拷给对方即可——纯 Markdown，不依赖任何特定 agent 平台。

用 Skills Manager 的：
```
skills install <指向本目录的路径>
skills deploy personal-agent-ops --agent <目标agent>
skills status personal-agent-ops
```
`install` 只进中央库，必须再 `deploy` 目标 agent 才会出现在该 agent 的可用技能里。

不用 Skills Manager 的 agent：把目录放进该 agent 的技能目录，或在其入口文件（如 AGENTS.md）里指向本目录的 SKILL.md。

## 定制

本规范刻意不写死人名、agent 名、磁盘路径和公司名，用角色名与相对路径占位。落地时各 agent 把自己的「团队档案目录」「巡检脚本路径」等填进占位符即可，不必改机制正文。
